# 字段规范（速查）

完整说明见 `模板/看板使用说明.md`；这里只给写 JSON 时最常查的表。

## 顶层

| 字段 | 必填 | 说明 |
|---|---|---|
| `标题` | ✓ | 显示在页面顶部 |
| `项目根` | | 相对看板目录的路径（如 `"../.."`）。不写则自动向上找含 `.git` 或 `AGENTS.md` 的目录 |
| `更新日期` / `更新人` / `说明` | | 显示在副标题 |
| `流程[]` | ✓ | 见下 |
| `AI接手{}` | ✓ | 驱动 `AI交接.md` 的内容，见下 |

## 流程对象

| 字段 | 必填 | 取值 |
|---|---|---|
| `id` | ✓ | 短代号，如 `A`、`L1` |
| `名称` | ✓ | 表格主标题 |
| `一句话` | ✓ | 主标题下的灰字 |
| `状态` | ✓ | `可用` / `部分可用` / `待修` / `阻塞` / `未开始` |
| `部分[]` | ✓ | 子项数组，**顺序 = 明细顺序 = 待办来源顺序** |
| `卡点[]` | | 整条链的卡点（字符串数组） |
| `更新` | ✓ | `YYYY-MM-DD` |

> 流程级 `完整度` **不要手写**，由生成器按权重算。

## 子项对象

| 字段 | 必填 | 取值 / 规则 |
|---|---|---|
| `名称` | ✓ | 具体动作，不写"整体优化" |
| `完整度` | ✓ | 0~100 整数；100 必须有可执行验证 |
| `说明` | ✓ | 做到哪一步；未完成要能看出"还差什么" |
| `卡点` | 条件 | 未完成且说明里没写"还差"时必填；写清缺谁/缺什么 |
| `权重` | | 1~5，默认 1（5 = 决定该模块能否交付） |
| `体量` | | `大` / `中` / `小`，默认 `小` |
| `阶段` | ✓ | 流程图按它分列；同阶段 = 可并行 |
| `文件[]` / `文档[]` | | 相对项目根、用 `/` 分隔、必须真实存在 |

## `AI接手` 子块

| 键 | 作用 | 缺失后果 |
|---|---|---|
| `读序[]` | 第 1 节 | 体检报错 |
| `环境{}` | 第 2 节 | 体检报错 |
| `常用命令[]` | 第 3 节（每项含 `用途`/`命令`/`期望`） | 体检报错 |
| `禁止事项[]` | 第 4 节（每项含 `事`/`原因`/`证据`） | 体检报错 |
| `既定结论[]` | 第 5 节 | 体检报错 |
| `验证归属[]` | 第 7 节（`流程`/`命令`/`期望`） | 体检报错 |
| `同步协议[]` | 第 8 节 | 体检报错 |
| `延伸阅读[]` | 生成 MD 结尾的"更细步骤去哪读" | 可缺省 |
| `检查项.根目录AGENTS` | `fail` / `warn` / `off`，控制是否检查项目根 `AGENTS.md` | 可缺省（默认 fail） |

第 6 节（待办队列）与第 9 节（文件索引）、第 10 节（进度快照）由生成器自动产出，不需要写。

## 体检会拦住什么

- 完整度不是 0~100 整数；权重不是 1~5；体量不是 大/中/小；状态不在 5 个合法值里
- **100% 却还挂着 `卡点`**（自相矛盾）
- **未完成却既没 `卡点`、说明里也没写「还差：…」**
- 缺 `阶段`
- `文件`/`文档` 用了反斜杠、写成绝对路径、或指向不存在的文件
- 同一流程内子项重名、流程重名、`AI接手` 缺必填节
- 一个流程只有 1 个阶段（会退化成一条线）→ **警告**
- 说明短于 8 字 → **警告**
