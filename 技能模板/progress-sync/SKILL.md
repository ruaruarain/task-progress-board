# 进度同步标准（progress-sync）

> **触发方式（先读这段）**
>
> 本技能**永不自动执行**。只有两种情况才执行：
> 1. 用户明确说："同步""同步进度""更新看板""刷新交接文档""收工同步"；
> 2. 你在**结束一段任务时主动问了一句**「这次进度要不要同步进看板？」，并得到**明确同意**。
>
> 除此之外：**不要**跑 `同步.py`、**不要**改 `看板数据.json`、**不要**"顺手把状态补齐"。
> 只如实报告做了什么 + 证据数字，然后把决定权交回用户。

## 为什么要有标准

看板之所以能"一眼看懂 + AI 能接手"，靠的是三件事同时成立：**单一数据源、可验证的完成度、两个产物永远一致**。
任何一次"顺手改一下"，都会让这三条同时失效。所以同步是有固定动作的。

```
看板数据.json   ← 唯一数据源（人可读，AI 可读）
      │  同步.py = 体检 + 生成 + 自检
  ┌───┴────────────┐
  ▼                ▼
任务看板.html    AI交接.md
（人：点击展开）  （AI：待办队列/禁忌/命令）
  └──► _自检.py ◄──┘   校验两者数字一致
```

## 一条命令

```powershell
$env:PYTHONIOENCODING='utf-8'
"${PY}" -X utf8 "${看板目录}/同步.py"
```

| 模式 | 用途 |
|---|---|
| `同步.py` | 完整流程：体检 → 生成两个产物 → 自检（**默认用这个**） |
| `同步.py --check` | 只校验不生成：数据质量 + 产物是否落后于数据源 |
| `同步.py --lint` | 只做数据体检 |
| `同步.py --quick` | 生成 + 自检，跳过体检（确认只改了数字时用） |

**退出码 0 = 一切一致；非 0 = 必须修完再收工。**

## 四阶段

### 1 采集

把你这次做的事落成事实：

- [ ] 改了哪些文件（精确路径）
- [ ] **可复核的证据**：命令输出、数字、对账结果
- [ ] 影响哪些流程 / 子项
- [ ] 新增或清掉了哪些卡点

> 没有证据的进度不要写进看板。凭"我觉得差不多了"填 100%，是这套标准最要禁止的行为。

### 2 录入（只改 `看板数据.json`）

**字段规范**

| 字段 | 必填 | 取值 | 规则 |
|---|---|---|---|
| `名称` | ✓ | 字符串 | 一个具体动作或模块，不写"整体优化"这类含糊词 |
| `完整度` | ✓ | 0~100 整数 | 只认可验证的程度（见下） |
| `说明` | ✓ | 字符串 | 做到哪一步；未完成的必须能看出"还差什么" |
| `卡点` | 条件 | 字符串 | 未完成且说明里没写"还差"时**必须**有；写清缺谁/缺什么 |
| `权重` | | 1~5 整数，默认 1 | 1 普通 / 2~3 重要 / 4~5 决定该模块能否交付 |
| `体量` | | 大/中/小，默认 小 | 大 ≥3 天 / 中 半天~2 天 / 小 半天内 |
| `阶段` | ✓ | 字符串 | 流程图按它分列；**同阶段=可并行**，阶段间=先后 |
| `文件` / `文档` | | 字符串数组 | 相对项目根、用 `/`；必须真实存在 |
| `更新`（流程级） | ✓ | `YYYY-MM-DD` | 改了哪条流程就更新哪条 |

**完整度判定**

| 填什么 | 什么时候可以填 |
|---|---|
| **100** | 有**可执行的验证**跑过并通过（断言全过 / 对账 0 差异 / 数字对得上）。拿不出验证方式的，不许填 100 |
| **70~99** | 主体可用，但有明确已知缺口（写进"还差"） |
| **30~69** | 部分实现，核心环节还缺 |
| **1~29** | 起了个头，或存在致命错误导致不可用 |
| **0** | 完全没做，或卡在外部资源 |

**卡点 / 还差 的写法**：不是写现象，是写**下一步要什么**。

- ❌ `效果不好`
- ✅ `需产品确认：列表默认按创建时间还是更新时间排序`
- ✅ `还差：把 A 流程的只读账号申请下来后重跑联调`

### 3 生成

跑 `同步.py`。它会：体检（字段/取值/路径存在性/卡点与完成度矛盾/重名）→ 重写 `任务看板.html` 与 `AI交接.md` → 跑 `_自检.py`（DOM、结构、10 节齐全、**快照数字与 JSON 一致**）。

### 4 验收

- [ ] `同步.py` 退出码 0，末行 `✅ 同步完成，一切一致`
- [ ] 体检 0 错误（警告尽量清零）
- [ ] 浏览器刷新 `任务看板.html`，点开你改的那条流程，肉眼确认
- [ ] 新增/删除文件时，`文件`/`文档` 已同步
- [ ] 在项目工作日志里追加一条：做了什么 / 证据数字 / 卡点

## 三条硬纪律

1. **不手改生成物**：`任务看板.html`、`AI交接.md` 是产物；要改内容就改 JSON。
2. **不跳过体检**：`--quick` 只在"只改数字、不动结构"时用。
3. **不虚高**：每个 100% 都要能说出"我用什么命令验证的"。

## 联动项

| 你改了什么 | 还要同步 |
|---|---|
| 子项完成度/说明/卡点 | 流程级 `更新` 日期 |
| 新增/删除文件 | 该子项的 `文件`/`文档`；`AI接手.常用命令` |
| 推翻/修正旧结论 | `AI接手.既定结论` + `AI接手.禁止事项` |
| 改了环境（装包等） | `AI接手.环境` |

## 什么时候**不**用

- 只读、回答问题、做分析但没产生项目进度 → 不用同步
- 只改了报告正文、没影响完成度与卡点 → 可以不同步（但影响结论时必须同步）
